Interface languages, script support and proofing per language. How translation works (adding a language, the embedded catalogs): crates/ui-egui/src/i18n.rs. The catalogs, their format and the clean-room rule live in storytold/craft-i18n (locales/<locale>/wordcraft.tsv and the shared common.tsv).

Dimension: ~29% (estimated; 28% before Italian proofing, 27% before Portuguese proofing, 25% before Polish and per-run proofing languages), 70–115 h to full for the twelve key languages plus ~45 h for the other ~17 languages Word ships, plus native-speaker review (human).

What Word ships (measured by listing the bundle)

  • 30 interface languages (31 .lproj folders incl. Base): ar, cs, da, de, el, en, en-GB, es, es-MX, fi, fr, fr-CA, he, hu, id, it, ja, ko, nl, no, pl, pt (BR), pt-PT, ru, sk, sv, th, tr, zh-CN, zh-TW. Arabic and Hebrew get a mirrored interface. No Hindi or Vietnamese interface on Mac.
  • 120 proofing tools (SharedSupport/Proofing Tools): spellers for ~50 languages, grammar checkers for ~20, hyphenators for ~16, thesauri for ~20.

What WordCraft ships (measured)

  • 27 interface languages: English plus zh-hans, zh-hant, ja, Korean ko (#1216), uk, es, pt-br, Serbian sr/sr-latn (#250), Estonian et, Turkish tr, Russian ru, Italian it (#594), German de (#574), Polish pl, Czech cs, Hungarian hu, French fr, Bulgarian bg, Vietnamese vi (#1434), Swedish sv (#1219), Croatian hr (#1271), Romanian ro, Slovenian sl, Dutch nl and Danish da (#2722). Catalogs have 2,061–2,674 entries each; Polish has every key of every other catalog, including the built-in style names and the equation gallery, except the citation style names only Hungarian, Bulgarian, Swedish, Romanian and Slovenian translate so far. A missing translation falls back to English and never fails a test or build. cargo xtask i18n-report, part of cargo xtask ci, prints per language the interface strings its catalog lacks: everything the interface audit saw looked up, the ribbon tabs, command labels and ribbon locations, the File › Home greetings, disabled-control reasons and the equation gallery. The catalogs are embedded at build time from craft-i18n (CRAFT_I18N_DIR, the commit in craft-i18n.rev; a build without it is English only), and craft-i18n's checker applies the format checks to every language alike (rows parse, no duplicate keys, placeholders match the English, plural forms, ellipses); the report also lists rows the crate skips and strings kept in English. Font tests check that the bundled faces have a glyph for each catalog's letters. Tests of the lookup code (English fallback, contexts, placeholder templates, built-in style names, the per-thread language, command search) use small inline catalogs or the pseudo-language, so rewording a translation never fails a test. pl, pl-PL and pl_PL.UTF-8 system locales pick Polish automatically.
  • Of the 675 English strings a scan extracts from tl!(…) calls and command labels/locations, each catalog covers 661 (98%). Some newer dialog and pane strings (Equation tab tooltips, Zotero, Read Aloud) aren't wrapped in tl! yet, so they show in English in every language: the true share of visible strings is ~93–95% (estimated).
  • Pending PRs: Norwegian Bokmål (#208) and Nynorsk (#210), Hebrew with RTL (#20).
  • Proofing: English, Polish, Portuguese, Italian, Russian, Czech, Indonesian and Spanish, chosen per run from its language (w:lang, resolved through the styles; Review › Language and the status bar set it: a short list, plus Set Proofing Language… for any of 38 languages and Set As Default for the document and future blank documents). Languages without proofing tools get the styles; Review › Language and the status bar set it). Languages without proofing tools get no spelling or grammar marks (as in Word without the language's tools) instead of being flagged as English. Detail in Proofing per language.
  • Document scripts: shaping via HarfRust (HarfBuzz port) for every script; bidi (UAX #9) and Arabic shaping tested (#207); IME on all desktop platforms (winit fixes pending, #155–#164).

When no saved proofing-language default exists, Polish, Portuguese and Czech interfaces write new documents and opened TXT/Markdown text in their proofing languages (pl-PL, pt-BR, cs-CZ). A Spanish interface writes them in the region's Spanish: es- plus the system region when that region's language is Spanish (es-UY on a Uruguayan system, es-MX on a Mexican one), else Spain's es-ES (#3360).

Interface audit (runs in CI). cargo xtask i18n-report runs untranslated_interface_text, which lays the app out in a pseudo-language (every tab, File page, dialog, pane, the right-click menu, and a hover and a click on every ribbon control) and fails on visible text that skipped the catalog. It then prints the missing-translation report described above, which never fails. Proper names (citation styles such as APA or GOST, LaTeX, Unicode) and bad parameters: errors, which name a command's JSON parameters for scripts and MCP, stay English. Size labels (Envelopes, Labels, Layout › Size) are translated patterns ({name} {height} × {width} in) with the region's decimal separator; paper names other than envelopes (Letter, Legal, A4, B5 (JIS)) stay as they are (#1128). The report's disabled-control reasons (the reason a ribbon hint gives for a greyed-out control, #1086, #2678) are read from every command's enabled check in the engine's command sources.

Set Proofing Language › Set As Default keeps the chosen language in user preferences across restarts (#2882), taking precedence over the interface language for blank documents and plain-text/Markdown files. Existing DOCX and built-in English templates keep their own language. Ordinary selection-language changes do not change this preference; older settings keep following the interface language. A rejected command, including a final protected-region check, retains the previous saved default. This does not install dictionaries or add proofing support.

Sorting and numbers in the text's language

Sorts follow the alphabet of the text's language (w:lang, else the document default): Table › Sort, Home › Sort, the index and its letter headings, the bibliography and the Table of Authorities. Letters with diacritics sort with their base letter (é with e) unless the language makes them letters of their own: Polish ą ć ę ł ń ó ś ź ż, Czech/Slovak č ch ř š ž (and Slovak ä ô), Hungarian cs dz dzs gy ly ny sz ty zs ö ü, Swedish/Finnish å ä ö and Danish/Norwegian æ ø å after z, Spanish ñ, Turkish, Croatian/Bosnian/Serbian Latin, Romanian, Estonian, Latvian, Lithuanian, Slovenian and Icelandic (crates/doc/src/collate.rs, a hand-written per-language alphabet table; full CLDR collation is not used). Table sort and table formulas read numbers with the language's decimal and group separators (1 250,50 in Polish, 1.250,50 in German, 1,250.50 in English) and write formula results with its decimal separator (crates/doc/src/locale_number.rs). Cuban and Peruvian Spanish (es-CU, es-PE) use decimal points (1,234.50), matching the existing region settings and CLDR's Latin American Spanish parent locale; cuban_and_peruvian_numbers_use_decimal_points covers parsing and result formatting. Interface lists (styles, fonts) still sort by code point.

Russian (ru) sorting keeps ё with е (a secondary diaeresis difference), before ж. Composed and decomposed ё and й have the same keys and index headings; the stored text is unchanged. Tests cover Russian locale aliases, case, representative words and these two canonical pairs. This is a narrow Cyrillic correction, not full Unicode normalization or CLDR collation. Ordering reference: Unicode CLDR Russian collation chart.

Region conventions (#838)

As in Word, a new blank document takes its paper from the system region, not the interface language: US Letter in the territories CLDR lists for it (US, Canada, Mexico, the Philippines, Chile, Colombia, Venezuela and a few Central American ones), A4 everywhere else. Lengths are shown in inches in the US (and Liberia, Myanmar) and centimetres elsewhere, written with the region's decimal separator (2,54 cm in Poland, Germany, France…); fields take either separator and any unit (1 in in a centimetre field). An explicit File › Options › Advanced › Measurement units choice still wins; its Automatic entry follows the region again.

Where the region comes from:

  • File › Options › Advanced › Region (saved; agents: file.options {"region": "pl-PL"}, auto returns to the system's);
  • else WORDCRAFT_REGION or LC_ALL;
  • else, on Unix, each convention from its own locale: numbers from LC_NUMERIC (else LANG), paper from LC_PAPER, measurement from LC_MEASUREMENT;
  • else the platform's preferred locale: the macOS preferred locale (en-PL), the browser's language on the web, and on Windows the home location (Settings › Time & language › Region) with the display language. Word follows Windows' regional format instead, so an en-US format set by someone living in Germany gives A4 and a decimal comma here; reading the regional format needs Win32 calls that are unsafe in Rust, which WordCraft forbids.

Runs without preferences (WORDCRAFT_NO_PREFS) stay en-US unless WORDCRAFT_REGION is set, so agents and screenshots give the same result on every machine. The decimal separator belongs to the language's own number format (CLDR): a decimal-comma language uses a comma everywhere except where CLDR says otherwise (de-CH), and English, whose en-XX locales follow the territory, uses a comma in decimal-comma territories (en-DE, en-PL). Other decimal-point languages keep the point in any territory (ja-PL is 2.54 cm), as CLDR's fallback to the language gives.

Templates (Letter, Resume, Report) keep their own size. Not yet: Word's "Default paper size" preference of its own, and Word's locale-specific Normal margins (2,5 cm in some regions; WordCraft keeps 2,54 cm).
